# NMIMS MBA Project Kit: instructions for AI agents

Read this first. It applies to every agent app (Claude Code, Codex, Antigravity, Gemini CLI, Cursor, GitHub Copilot) working anywhere in this repository.

## What this kit does
It helps a student produce an NMIMS CDOE online MBA Semester IV project (Problem-Solving Proposal, Business Plan or Research Project) as two deliverables: a submission-ready **PDF** that follows the university's layout rules, and a viva **PowerPoint deck**. The student is the author; the kit provides structure, research discipline, writing quality, originality checks and the build.

## Skills (in `skills/`, Agent Skills format; also linked at `.claude/skills/` and `.agents/skills/`)
| Skill | Use it for |
|---|---|
| `nmims-mba-project` | The whole method: intake questions, project folders, chapter skeletons per rubric, evidence and citations, financial model, PDF and deck builds, final checks |
| `originality-check` | Plagiarism (against sources and the web) and copy cases (against every other project in `projects/`) |
| `humaniser` | Clear, natural writing in the student's own voice (use academic mode for reports) |
| `clean-user-facing-text` | Removing hidden Unicode and checking sentence rhythm |

If your app does not load skills automatically, open the relevant `skills/<name>/SKILL.md` and follow it.

## Commands (in `commands/`; app-specific copies are generated by `scripts/sync_agent_files.py`)
`/new-project`, `/continue-project`, `/survey`, `/write-chapter`, `/humanise`, `/originality-check`, `/verify-sources`, `/build`, `/finalise`, `/setup`. If your app has no slash commands, open `commands/<name>.md` and follow it.

## Rules (always)
1. **Ask before assuming.** Start every new project with the intake rounds in `skills/nmims-mba-project/references/intake.md`: project name and type first, then the Semester III pre-work from the portal and any work already done, then the idea in the student's own words, then type-specific questions. Ask again whenever a decision belongs to the student.
2. **Always offer a survey** for the project (`skills/nmims-mba-project/references/survey.md`). The student may skip it; record the decision.
3. **One folder per project** in `projects/<student>-<topic>/`. Never copy text, data, numbers, figures or reflections between projects. `projects/` is git-ignored and must never be committed.
4. **Never invent** sources, statistics, quotes, interviews, survey results, organisations' internal data or personal experiences. Unknowns become `[NEEDS: ...]` (only the student can supply) or `[VERIFY: ...]` (check a primary source).
5. **Original and in the student's voice.** Write from the student's material, cite every source, run the humaniser (academic mode) and the originality check before any final build. Do not use tricks that hide copying (synonym spinning, hidden characters).
6. **Finish every check and report it honestly.** The originality check has two parts and both must be complete: the local check (sources + other projects) and the exact-phrase web check, where **every** phrase in `output/web_check.md` is searched and recorded, not a sample. Report exact numbers ("local 0.4%, PASS; web 14 of 14 phrases searched, 0 matches") and the date. Never say a check is done or passed while any part is unfinished; say what is left. Re-run both after any chapter edit.
7. **Final outputs are a PDF and a PPT,** built with the project's `tools/` (`npm run build`, `npm run deck`). The final PDF build refuses to run until placeholders are resolved, the originality report passes and the web check is complete, all after the last chapter edit.
8. **Tools:** if something is missing, run `/setup` (or `bash scripts/setup.sh`), which asks before installing anything.
